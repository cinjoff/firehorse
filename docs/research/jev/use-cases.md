## The one architectural pattern

236 of the 240 verified projects keep deterministic code in charge of what
actually executes, with Jev answering a bounded question at a branch point. This
holds across categories that otherwise share nothing: a Tetris player, a
Hyperliquid trading desk, a Claude Code hook, and a Postgres extension all have
the same shape.

Stated as a rule: **code enumerates the options, Jev picks one, code executes.**

The projects that read best are explicit about it.
[`valentynkit/jev-plays-pokemon-red`](https://github.com/valentynkit/jev-plays-pokemon-red)
has deterministic code own the route and the arithmetic, and calls Jev only at
branches. [`thelau/jev-tetris`](https://github.com/thelau/jev-tetris) enumerates
every reachable placement including tucks and spins, writes each as an English
sentence, and asks Jev for a probability over all of them.

This is not stylistic. It follows from the documented failure modes: a model
that cannot count, cannot do arithmetic, and reads instructions literally is
only safe when the option set is generated by something that can.

## Agent guardrails

27 projects, 21 of them aimed at agentic development. The densest concentration
of agentic-development work in the ecosystem, and the most interesting one.

The job is the same everywhere: a coding agent is about to do something, or
claims to have finished something, and Jev renders a verdict before the code
proceeds. Three sub-patterns are distinct enough to name.

**Tool-call gating.** Jev scores a pending tool call and the host decides.
[`leepokai/jev-guard`](https://github.com/leepokai/jev-guard) does
prompt-injection and dangerous-action screening for Claude Code, Codex, Pi, and
ACP agents. [`y0usaf/pi-jev`](https://github.com/y0usaf/pi-jev) adds a measured
gate to Pi. [`jomatsu/pi-jev-auto-mode`](https://github.com/jomatsu/pi-jev-auto-mode)
approves `bash`, `write`, and `edit` semantically and **fails closed** when it
cannot decide, which is the right default and not the common one.
[`vercel-labs/fx`](https://github.com/vercel-labs/fx) ships a
`typesafe_permission_reviewer` builtin so its coding agent's permission
decisions run through Jev instead of an LLM call.

**Completion verification.** This is the pattern with the most independent
reinvention, which says something about how much agents lie about finishing.
[`valentynkit/jev-belay`](https://github.com/valentynkit/jev-belay) is a Claude
Code Stop hook that checks the transcript for evidence before trusting a "done"
claim, spends exactly one four-question call and only when files changed with no
passing check since, and fails open on every error path.
[`thruwire/foreman`](https://github.com/thruwire/foreman) sits above Codex
workers and judges whether an implementation is complete, its tests sufficient,
or a human needed. [`different-ai/openwork`](https://github.com/different-ai/openwork),
the largest adopter in the whole ecosystem at 23.7k stars, wires Jev into its
eval testkit as a verification judge so agent-produced work is gated by typed
verdicts rather than a text model.

**Policy and rule compliance.**
[`coldteadotai/abide`](https://github.com/coldteadotai/abide) reads every edit a
coding agent makes and flags rule violations. It is also the only project in the
corpus that publishes a precision number: an independent reviewer confirmed 10
of 39 flagged edits and 11 of 15 flagged tests. Roughly 26% precision on edits
and 73% on tests. That is a real result, it is unflattering on one axis, and the
fact that its precision is unflattering on one axis is exactly the kind of
number the guardrail category otherwise lacks. Measurement does exist in this
ecosystem, but it is concentrated in a separate evaluation cluster rather than
in the tools themselves; see [Evaluation and calibration](#evaluation-and-calibration).

[`shiftynick/jev-axi`](https://github.com/shiftynick/jev-axi) is worth a look as
a CLI rather than a hook: blocking risky tool calls, screening fetched content
for injection, triaging build logs, and flagging risky diffs from the shell.

## Agent and model routing

25 projects. The pitch is straightforward: choosing which model handles a turn
is a classification problem, and paying a frontier model 4 to 14 seconds to make
it is absurd.

Per-turn routing for existing agents is the bulk.
[`gargpratyush/jev-router`](https://github.com/gargpratyush/jev-router) wraps
Claude Code and Codex and sends simple work to a fast tier, hard work to a
strong tier. [`0xNatoshi/jev-codex-router`](https://github.com/0xNatoshi/jev-codex-router)
picks model, thinking depth, and speed mode per Codex turn.
[`aaronshaf/opencode-jev-orchestrator`](https://github.com/aaronshaf/opencode-jev-orchestrator)
inverts it: keep the parent model fixed and delegate only the hard turns to
temporary subagents.

Skill and tool selection is the same mechanism pointed at a different set.
[`Dicklesworthstone/skillranker`](https://github.com/Dicklesworthstone/skillranker)
ranks which agent skill fits the next step from live session context and can
abstain. [`GodsBoy/jev-agent-skill-router`](https://github.com/GodsBoy/jev-agent-skill-router)
declines weak matches rather than guessing. Abstention is the feature: a router
that returns low confidence and hands back to the LLM is more useful than one
that always answers.

[`BillionsBobby/JevRouter`](https://github.com/BillionsBobby/JevRouter) is the
most complete statement of the pattern. Jev makes the Choice; the host then
filters by availability, permissions, risk, and confirmation before anything
executes.

For evidence rather than claims,
[`vinilana/jev-eval-agent`](https://github.com/vinilana/jev-eval-agent) compares
LLM tool selection against Jev routing in a harness with 100 mocked tools.

## Context engineering

9 projects, 5 aimed at agentic development. Small category, high leverage: the
question "is this tool result still worth keeping" is asked hundreds of times
per session and is pure classification.

[`tamaratran/fast-jev-compaction`](https://github.com/tamaratran/fast-jev-compaction)
is the flagship at 4.6k stars. It replaces Claude Code's compaction summary
entirely, scoring every tool call and result for whether it is still needed
rather than summarizing. Retained text stays verbatim, which is the point:
summarization loses exact tokens, and exact tokens are what code needs.

[`GhalebDweikat/winnow`](https://github.com/GhalebDweikat/winnow) moves the
decision earlier, judging tool results before they enter context at all.
[`Nyarlathoteppppp/pi-jev-context`](https://github.com/Nyarlathoteppppp/pi-jev-context)
adds the sharpest engineering detail in the category: it shortens long tool
output block by block **so that no cached prompt prefix is invalidated**. That
constraint, preserving the prefix cache, is invisible in a naive design and
dominates the actual economics.

The honest caveat, which cobanov's list states and I will repeat: preserving
retained text verbatim does not prove the omitted history was unnecessary. None
of these projects measures what pruning cost.

## SDKs, clients, and developer tooling

48 projects, the largest category and the least interesting individually. Jev's
interface is small enough that a competent client is an afternoon's work, so
there is one for nearly every language: Go, Elixir, Haskell, R, Ruby, Java,
Laravel, PHP. Official SDKs are `typesafe-ai/typesafe-sdk-js` and
`typesafe-ai/typesafe-sdk-python`.

The ones worth knowing are the ones that are not clients.
[`vercel-labs/json-render`](https://github.com/vercel-labs/json-render) at 17.0k
stars uses Jev in its compose path to pick which components and actions a
rendered interface should contain, which is generative UI with the generation
removed. [`vercel/eve`](https://github.com/vercel/eve) ships Jev as the default
evaluation model in its experimental evaluate path.
[`sutro-sh/jev-align`](https://github.com/sutro-sh/jev-align) is an
active-learning CLI: Jev evaluates rows, surfaces the uncertain ones for human
labelling, and GEPA proposes revised decision definitions. That is the only
project treating question design as something to iterate on systematically, and
given the literal-reading failure mode it may be the most valuable tool here.

MCP servers are their own cluster: `BYK/jev-mcp` is eval-first,
`blakestone-x/jev-mcp` exposes classify, score, check, match, and screen,
`itsmostafa/typesafe-mcp` is a general connector.

## Browser and computer use

18 projects. The category where the latency claim is load-bearing rather than
rhetorical, because a browser agent makes a decision per step and a 4-second
step makes the whole loop unusable.

[`browser-use/jev-ultrafast`](https://github.com/browser-use/jev-ultrafast) at
10.4k stars is the reference implementation and the clearest statement of the
hybrid: Jev picks an operation and a DOM element in one request, and a small LLM
writes text only for `TYPE_TEXT`. The division of labour is exact. Jev chooses
from what exists; the LLM produces what does not.

[`awlevin/typesafe-computer-use`](https://github.com/awlevin/typesafe-computer-use)
runs the same loop against macOS via OCR and reports roughly $0.0002 per step.
[`droidrun/mobile-jev`](https://github.com/droidrun/mobile-jev) drives a real
Android device, and its published Uber demo deliberately stops before booking.
[`Ying-Kai-Liao/jev-browser`](https://github.com/Ying-Kai-Liao/jev-browser) has
an LLM plan the outcome while Jev decides each click on a Playwright snapshot at
about 300ms per call.

These operate real browsers and devices when enabled. Published demos have
task-specific success criteria and none of them establishes general reliability.

## Data, search, and retrieval

14 projects. Jev as a predicate or a reranker.

The database extensions are the most novel thing in the corpus.
[`realZachi/pg-jev`](https://github.com/realZachi/pg-jev) and
[`giuliosmall/pg_typesafe`](https://github.com/giuliosmall/pg_typesafe) expose
judgments from Postgres. [`kylemclaren/jevql`](https://github.com/kylemclaren/jevql)
lets you write `WHERE jev(alias, 'condition')`, with the plain SQL running
server-side first and the client applying the resulting filter.
[`colliber/duckdb-jev`](https://github.com/colliber/duckdb-jev) does the DuckDB
equivalent. [`jexp/neo4jev`](https://github.com/jexp/neo4jev) is the cleverest:
at each graph node Jev chooses which relationship to follow, with beam search
over log-probabilities.

For retrieval, [`hotchpotch/jev-reranker`](https://github.com/hotchpotch/jev-reranker)
and [`WiktorB2004/llama-index-jev`](https://github.com/WiktorB2004/llama-index-jev)
are drop-in rerankers.
[`zhuyansen/jev-search-rerank-eval`](https://github.com/zhuyansen/jev-search-rerank-eval)
is the one to read first: it compares Jev reranking against lexical, embedding,
and fusion baselines, and includes a judge-circularity analysis.

## Domain applications

27 projects. Mostly finance, with trading the dominant vertical because it
shares browser use's latency sensitivity.

[`OpenByteInc/QuantDinger`](https://github.com/OpenByteInc/QuantDinger) at 11.8k
stars uses Jev as an optional, auditable PASS/REJECT gate on strategy and quick
trade entry orders. [`jarrodwatts/jev-trader`](https://github.com/jarrodwatts/jev-trader)
and [`aowang-ai/jev-trade`](https://github.com/aowang-ai/jev-trade) both default
to dry runs, and both will place real orders with a configured key. Treat them
as demos.

Outside finance: [`usenotra/notra`](https://github.com/usenotra/notra) is a
production marketing-analytics platform with a flag that routes brand-visibility
classifiers off an LLM and onto Jev, which is the cleanest example of the
straight cost-substitution case.
[`kyotofin/tax-doc-classifier`](https://github.com/kyotofin/tax-doc-classifier)
classifies IRS form pages behind a confidence gate.
[`kitze/unclutter`](https://github.com/kitze/unclutter) and
[`realZachi/typesafe-adblock`](https://github.com/realZachi/typesafe-adblock)
both turn "is this element junk" into a stream of per-element typed questions.

## Open reproductions

16 projects, and the category exists for one reason: a fast model behind an HTTP
hop is not a fast model. This is the most-repeated structural objection in the
ecosystem.

[`logan-markewich/jeff`](https://github.com/logan-markewich/jeff) is a
self-hosted drop-in on a 400M GLiFormer that you point the official
`typesafe-sdk` at by changing the base URL.
[`TianyuCodings/NanoJev`](https://github.com/TianyuCodings/NanoJev) is a 0.6B
parallel decision model with its training pipeline.
[`zhengxuyu/litjev`](https://github.com/zhengxuyu/litjev) turns any Qwen model
into a decision model serving the same `/v1/systemone` schema with no training.
[`vinnylarouge/jevlike`](https://github.com/vinnylarouge/jevlike) hit 166 points
on Hacker News.

None is a reproduction of TypeSafe's architecture, RLCD training, or
calibration. They reproduce the interface, which is the part that matters for
portability and the part nobody can verify claims about.

## Games, simulation, and robotics

20 projects, none aimed at agentic development, and the best place to see the
architecture honestly because games have ground truth.

[`valentynkit/jev-plays-pokemon-red`](https://github.com/valentynkit/jev-plays-pokemon-red)
scores every battle turn's faint prediction against the emulator's RAM with a
Brier score. [`phyous/tsai-sc`](https://github.com/phyous/tsai-sc) ships a
verified run with a probability trace and an evidence bundle.

And then [`thelau/jev-tetris`](https://github.com/thelau/jev-tetris), which
ships a shuffled-probability control and a 23-line regex baseline over the same
sentences, and reports that the regex outscores the model. Publishing the
baseline that beats you is the most credible thing anyone in this ecosystem has
done.

## Evaluation and calibration

30 projects, and this category only exists because the first version of this
taxonomy did not have it. Without an option to put them in, the classifier
dumped benchmark repositories into `not-jev` and I nearly published the
conclusion that nobody measures anything. They do. See [method.md](method.md).

About 25 are genuine independent measurement, and the quality is higher than
anywhere else in the ecosystem. Several are pre-registered, most publish raw
responses, and a striking number report Jev losing.

[`scienthoon/jev-ood-calibration`](https://github.com/scienthoon/jev-ood-calibration)
is the most rigorous: 900 rule-generated support tickets the model cannot have
seen plus three public benchmarks, publishing every raw response and ECE.
[`jourdanlabs/assay-001`](https://github.com/jourdanlabs/assay-001) is a
pre-registered check of calibration and type safety on Banking77 and CLINC150,
with a split verdict and full logs.
[`yodablocks/jev-orderby-bench`](https://github.com/yodablocks/jev-orderby-bench)
asks a narrow and genuinely useful question, whether `ORDER BY` over a Jev
probability is defensible, behind a pre-registered gate on pairwise inversion.

The head-to-heads are where it gets uncomfortable for the marketing.
[`anisselbd/jev-phishing-bench`](https://github.com/anisselbd/jev-phishing-bench)
runs 2,000 emails against Claude Haiku 4.5 and reports plainly that Haiku wins
on accuracy. [`vclic/smoking-extraction-benchmark`](https://github.com/vclic/smoking-extraction-benchmark)
puts 1,000 synthetic notes against OpenAI structured outputs.
[`bitnovus/jev-spam-eval`](https://github.com/bitnovus/jev-spam-eval) benchmarks
against trained TF-IDF baselines and flags its own post-hoc tuning.
[`4esv/jev-eval`](https://github.com/4esv/jev-eval) compares against GPT-5.6
Terra on accuracy, calibration, latency, and cost together, which is the right
set of four.

For agentic work specifically,
[`baibizhe/jev-decision-benchmarks`](https://github.com/baibizhe/jev-decision-benchmarks)
evaluates on MetaTool, When2Call, and BFCL V4, focusing on tool selection and
abstention, and [`TokenTrim/jev-agent-failure-benchmark`](https://github.com/TokenTrim/jev-agent-failure-benchmark)
uses Who&When Pro with injected agent failures to test who-failed and
which-step attribution. Those two are the closest thing to evidence for or
against the guardrail and routing categories, and anyone adopting those patterns
should read them before the tools themselves.

## Media and creative

6 projects, the tail. [`trungdq88/youtube-sponsor-detection`](https://github.com/trungdq88/youtube-sponsor-detection)
and [`valentynkit/jev-skip`](https://github.com/valentynkit/jev-skip) both find
sponsor reads in captions; jev-skip reports catching 77% of SponsorBlock's
sponsor seconds across 23 videos at $0.0008 a video, which is a real number with
a real denominator. [`achimala/jevinci`](https://github.com/achimala/jevinci)
paints images by predicting every pixel's colour in parallel, which is a
category error executed deliberately and worth the click.

## Where this points for Firehorse

Firehorse is a workflow framework for coding agents, so the relevant categories
are guardrails, routing, and context engineering: 61 projects, of which 38 are
explicitly agentic-development work.

Three patterns transfer without much adaptation.

**Skill selection is a Choice question.** Firehorse projects definitions into
slash commands, and an agent picking which workflow applies is exactly the
`skillranker` shape. The abstention behaviour matters more than the accuracy:
declining a weak match and handing back is the correct output.

**Workflow gates are Noul questions.** `/firehorse:build` and `/firehorse:fix-bug`
already derive and run a typecheck and test gate. A completion check in the
`jev-belay` shape, evidence in the transcript before a "done" claim is trusted,
is the same idea one level up, and belay's design rules are worth copying
wholesale: spend a call only when state changed, and fail open on every error.

**Drift checks are classification.** `upstreams-check` reports whether upstream
skill drift is breaking or advisory. That judgment is a Score over a rubric.

The honest counterweight: 46 of these 61 score below the midpoint between
"working experiment" and "usable library" on the readiness rubric, and exactly
one of them publishes a precision number. The measurement that does exist lives
in a separate evaluation cluster, so read
[`baibizhe/jev-decision-benchmarks`](https://github.com/baibizhe/jev-decision-benchmarks)
on tool selection and abstention before adopting the routing pattern. Anything adopted here should ship
with the measurement the ecosystem mostly skipped.
